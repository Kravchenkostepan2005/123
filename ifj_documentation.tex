\section{Způsob řešení jednotlivých částí projektu}

\subsection{Lexikální analýza}
Lexikální analýza je realizována dvojicí souborů \texttt{scanner.c} a \texttt{scanner.h}. Základní datovou jednotkou je struktura \texttt{Token}, která spojuje typ (\texttt{Token\_type}) a sjednocený obsah (\texttt{Token\_content}). Pomocné funkce \texttt{token\_assign\_char}, \texttt{token\_remove\_last\_char}, \texttt{save\_int}, \texttt{save\_float} a \texttt{token\_reset} zajišťují bezpečnou práci s dynamicky alokovanými řetězci i převody na číselné hodnoty. Všechny alokační chyby se propagují přes \texttt{set\_error()}, která token označí typem \texttt{ERROR} a nastaví návratový kód na \texttt{LEXICAL\_ERROR} nebo \texttt{COMPILER\_ERROR}.

Jádrem skeneru je deterministický konečný automat implementovaný ve funkci \texttt{state\_machine()}. Automat čte znaky z \texttt{stdin} (pomocí \texttt{fgetc}) a přechází mezi stavy vyjmenovanými v \texttt{enum State} (\texttt{START}, \texttt{CHECK\_COMMENT}, \texttt{IDENTIFIER\_OR\_KEYWORD}, \texttt{INTEGER\_CHECK}, \texttt{FLOAT\_CHECK\_EXPONENT}, \texttt{QUOTES\_STATE} atd.). Každý přechod může zapisovat aktuální znak do tokenu, měnit jeho typ nebo vracet znak zpět do proudu přes \texttt{ungetc}, pokud už k danému lexému nepatří. Funkce \texttt{get\_token()} jen alokuje nový token, zavolá \texttt{state\_machine()} a po dokončení vrátí plně naplněnou strukturu; uvolnění paměti je řešeno přes \texttt{free\_token()}.

Rozpoznávání lexémů pokrývá všechny symboly specifikace IFJ25:
\begin{itemize}
    \item \textbf{Klíčová slova a identifikátory}: Pole \texttt{keyword\_table} obsahuje 17 textových konstant (např. \texttt{"Ifj"}, \texttt{"class"}, \texttt{"Num"}, \texttt{"Null"}). Po dočtení lexému ve stavu \texttt{IDENTIFIER\_OR\_KEYWORD} se řetězec porovná s tabulkou a případně se token označí typem \texttt{KEYWORD}. Jinak vzniká \texttt{IDENTIFIER}. Zvláštní stav \texttt{UNDERSCORE\_STATE} a následný \texttt{GLOBAL\_IDENTIFIER\_STATE} rozpoznávají globální identifikátory začínající dvěma podtržítky (\texttt{GLOBAL\_IDENTIFIER}).
    \item \textbf{Číselné literály}: Stav \texttt{INTEGER\_CHECK} pokrývá celé číslo, rozlišuje prefix \texttt{0x} pro hexadecimální zápis (\texttt{INTEGER\_HEXADECIMAL}) a přechody do \texttt{FLOAT\_CHECK\_DECIMAL} a \texttt{FLOAT\_CHECK\_EXPONENT} pro čísla s desetinnou tečkou nebo exponentem. Po dokončení se textový buffer převádí na \texttt{int} nebo \texttt{float} a uloží do sdílené unie.
    \item \textbf{Řetězce}: Stav \texttt{QUOTES\_STATE} spouští načítání řetězců. Jednořádkové literály používají \texttt{STRING\_STATE} a podporují únikové sekvence (\texttt{\textbackslash{}n}, \texttt{\textbackslash{}t}, \texttt{\textbackslash{}xhh}). Trojité uvozovky přepínají do \texttt{ML\_STRING\_STATE}, kde čteme vícero řádků, odstraňujeme zakončení a normalizujeme odsazení pomocí stavů \texttt{ML\_STRING\_WHITESPACE\_*}. Výsledek je token \texttt{STRING\_TOKEN} nebo \texttt{ML\_STRING\_TOKEN}.
    \item \textbf{Operátory a oddělovače}: Základní symboly (\texttt{+}, \texttt{-}, \texttt{*}, \texttt{/}, závorky, složené závorky, čárka, tečka) se vracejí přímo ze stavu \texttt{START}. Kombinované operátory (\texttt{==}, \texttt{!=}, \texttt{<=}, \texttt{>=}) zpracovává stav \texttt{EXTENSION}. Tabulka vestavěných funkcí (\texttt{inbuilt\_functions\_table}) slouží parseru k ověření kvalifikovaných jmen typu \texttt{Ifj.write}.
    \item \textbf{Komentáře a whitespace}: \texttt{SPACE\_SKIP} ignoruje mezery, \texttt{CHECK\_COMMENT} rozlišuje jednořádkové komentáře \texttt{//} a vícerádkové \texttt{/* */}. Pro vícerádkové komentáře udržujeme čítač \texttt{depth} (stavy \texttt{ML\_COMMENT\_START}, \texttt{ML\_COMMENT\_END}, \texttt{ADD\_DEPTH}) a podporujeme vnořování. Po ukončení komentáře se vrací token \texttt{WHITESPACE} nebo \texttt{EOL}, aby parser dostal informaci o konci řádku.
\end{itemize}

Při nalezení chyby (neplatná sekvence, neočekávaný EOF, přetečení, špatný escape) se automat přepne do \texttt{ERROR\_STATE}, token se resetuje a funkce vrací \texttt{ERROR} s příslušným kódem chyby. Tím je zajištěno, že lexikální analýza předává parseru konzistentní proud tokenů a případné chyby hlásí deterministicky hned ve fázi čtení.

\subsection{Syntaktická analýza}
Parser je psaný v jazyce C jako rekurzivní sestup, který přímo implementuje pravidla z kapitoly~\ref{sec:grammar}. Vstupem je proud tokenů ze skeneru, výstupem strom \texttt{Node} popisující program (\texttt{PROGRAM}~$\Rightarrow$~\texttt{PROLOG}~\texttt{CLASS\_NT}). Kořen vytváří funkce \texttt{parse\_topDown()}, která postupně volá \texttt{prolog\_rule()} a \texttt{class\_rule()}. Každé pravidlo odpovídá samostatné funkci s příponou \texttt{\_rule}. Strom se skládá pomocí \texttt{insert\_child()}, jež přidá levého potomka (terminál) nebo pravého potomka (neterminál) podle pořadí zpracovávaných symbolů.

Čtečku tokenů tvoří dvojice \texttt{read\_buffer()} a \texttt{write\_buffer()} sdílející jednoprveňovou vyrovnávací paměť. Tím se dá bezpečně nahlížet na další token bez trvalého odebrání. Úpravu bílých znaků řeší \texttt{skip\_EOL\_WHITESPACE()}, která dokáže vyžadovat přítomnost EOL nebo jej ignorovat v závislosti na parametru. Na každém kroku se zavolá \texttt{error\_handler()}, jenž z tokenu typu \texttt{ERROR} vytáhne konkrétní chybový kód a ihned přeruší analýzu.

Podstatou parseru je generická funkce \texttt{check\_correct\_rule()}. Přijímá pole terminálů (\texttt{Token\_type terminals[]}), pole podřízených neterminálů (\texttt{Nonterminal\_type nonterminals[]}) a volitelně očekávané klíčové hodnoty (\texttt{Keyword\_type}). Prvkům \texttt{NaT} v poli terminálů odpovídají rekurzivní volání \texttt{call\_rule()}, která podle typu neterminálu přesměrují řízení do správné funkce (např. \texttt{FUNCLIST} $\rightarrow$ \texttt{func\_list\_rule()}). Speciální symboly \texttt{WHITESPACE\_EPSILON} a \texttt{EOL\_EPSILON} umožňují přeskakovat volitelné mezery a konce řádků bez duplikace logiky ve všech pravidlech. Jakmile některá větev vrátí chybový kód, \texttt{check\_correct\_rule()} chybu propaguje až na vrchol.

Zpracování jednotlivých konstrukcí:
\begin{itemize}
    \item \textbf{Prolog a deklarace tříd}: \texttt{prolog\_rule()} rozpozná posloupnost \texttt{import "ifj25" for Ifj} a uloží nalezený řetězec přímo do AST uzlu. \texttt{class\_rule()} očekává \texttt{class Program \{ EOL FuncList \}} následované \texttt{\} EOL? EOF}.
    \item \textbf{Seznam funkcí}: \texttt{func\_list\_rule()} zjišťuje, zda další token začíná klíčovým slovem \texttt{static}; pokud ne, přechází se na $\varepsilon$-produkci. V opačném případě se zpracuje \texttt{func\_decl\_rule()} definující hlavičku (\texttt{func\_head\_rule()}) i tělo funkce (\texttt{block\_rule()}).
    \item \textbf{Výroky}: \texttt{sequence\_rule()} rozlišuje deklarace \texttt{var}, příkazy \texttt{if}/\texttt{while}/\texttt{return}, přiřazení na lokální i globální identifikátory a bloky. Každý konstruktor využívá odpovídající neterminály \texttt{EXPR}, \texttt{BLOCK}, \texttt{ARGLISTOPT} apod.
    \item \textbf{Výrazy}: Neterminály \texttt{LOGICOR}, \texttt{LOGICAND}, \texttt{EQUALITY}, \texttt{ISEXPR}, \texttt{RELATIONAL}, \texttt{ADDITIVE}, \texttt{MULTIPLICATIVE}, \texttt{UNARY} a \texttt{PRIMARY} implementují precedenci operátorů. Každé pravidlo předá kontrolu \texttt{check\_correct\_rule()} s kombinací terminálů (např. \texttt{COMPARISON}, \texttt{NOT\_EQUAL}) a rekurzivních neterminálů (\texttt{ISEXPRTAIL}, \texttt{RELATIONALTAIL}).
    \item \textbf{Argumenty a termy}: \texttt{arg\_list\_opt\_rule()} a \texttt{arg\_tail\_rule()} podporují seznamy oddělené čárkami včetně literálů, identifikátorů, globálních identifikátorů i klíčového slova \texttt{null}. Funkce \texttt{primary\_ident\_tail()} zjišťuje, zda identifikátor pokračuje voláním \texttt{(...)}.
\end{itemize}

Parser tedy přímo aplikuje definovanou LL gramatiku a prochází AST pouze jednou. V kombinaci se skenerem tím vzniká deterministický překladač, jenž hlásí chyby s přesnými kódy (\texttt{SYNTACTICAL\_ERROR}, \texttt{COMPILER\_ERROR}) a zachovává přehlednou návaznost mezi pravidly a implementací.

\subsection{Zpracování výrazů pomocí precedenční logiky}
Precedenční logiku má na starosti funkce \texttt{precProces} v souborech \texttt{precedencna.c} a \texttt{precedencna.h}, která se volá pro každý token ve výrazu. Na strukturovaný zásobník \texttt{StackNode} přidá token a může provést zjednodušení podle pravidel precedenční tabulky. Použitá pravidla ukládá na samostatný zásobník, jenž je následně předán tokenu před výrazem pro jednodušší přístup a manipulaci. Po celý čas probíhá typová kontrola, aby byla zajištěna správnost výsledné hodnoty.

\subsection{Generátor kódu}
Generování kódu zajišťuje funkce \texttt{codeGen} v souborech \texttt{interpret.c} a \texttt{interpret.h}. Tato funkce prochází seznam tokenů podle předdefinované logiky. Podle prvního tokenu volá specializované funkce pro daný příkaz. Každá z nich využívá pomocné tiskové funkce, které na \texttt{stdout} generují trojadresné instrukce pro interpret \texttt{IFJcode24}. Současně využívá strukturu \texttt{StackNode}, do níž ukládá pořadí zanoření příkazů, například \texttt{while} a \texttt{if}. Při práci s výrazy se používají pravidla precedenční logiky uložená v položce \texttt{rules} předchozího tokenu, čímž se zaručí správný výpočet.

\subsection{Tabulka symbolů TRP-izp}
Tabulka symbolů je implementována jako strukturovaná hashovací tabulka \texttt{HashItem} podle varianty zadání TRP-izp v souborech \texttt{symtable.c} a \texttt{symtable.h}. Má na starosti spravovat uživatelem definované proměnné a funkce spolu s předdefinovanými funkcemi \texttt{ifj.xxx}. Tabulka používá "magic number" \texttt{hashNumber} 5381 pro optimální mapování položek. Obsahuje informace o typu \texttt{const}/\texttt{var}, parametrech funkcí ve struktuře \texttt{symItems}, lokální skupině, úrovni zanoření a o tom, zda byla proměnná inicializována nebo definována.

\subsection{LL gramatika}\label{sec:grammar}
Aktuálně používaná LL gramatika je uvedena níže. V této verzi dokumentu uvádíme pouze textový zápis pravidel.

\begin{enumerate}[label=R\arabic*.]
    \item Program $\rightarrow$ Prolog Class
    \item Prolog $\rightarrow$ \texttt{ident("import")} \texttt{STRING("ifj25")} \texttt{ident("for")} \texttt{KEYWORD(Ifj)} EOL
    \item Class $\rightarrow$ \texttt{class} \texttt{ident("Program")} \{ EOL FuncList \}
    \item FuncList $\rightarrow$ FuncDecl FuncList
    \item FuncList $\rightarrow$ $\varepsilon$
    \item FuncDecl $\rightarrow$ \texttt{static} ident FuncHead Block EOL
    \item FuncHead $\rightarrow$ ( ParamListOpt )
    \item FuncHead $\rightarrow$ = ( ident )
    \item FuncHead $\rightarrow$ $\varepsilon$
    \item ParamListOpt $\rightarrow$ ParamList
    \item ParamListOpt $\rightarrow$ $\varepsilon$
    \item ParamList $\rightarrow$ ident ParamTail
    \item ParamTail $\rightarrow$ , ident ParamTail
    \item ParamTail $\rightarrow$ $\varepsilon$
    \item Block $\rightarrow$ \{ EOL StmtList \}
    \item StmtList $\rightarrow$ Stmt EOL StmtList
    \item StmtList $\rightarrow$ $\varepsilon$
    \item Stmt $\rightarrow$ \texttt{var} ident
    \item Stmt $\rightarrow$ \texttt{if} ( EXPR ) Block \texttt{else} Block
    \item Stmt $\rightarrow$ \texttt{while} ( EXPR ) Block
    \item Stmt $\rightarrow$ \texttt{return} EXPR
    \item Stmt $\rightarrow$ ident = AfterAssign
    \item Stmt $\rightarrow$ gident = EXPR
    \item AfterAssign $\rightarrow$ FuncName ( ArgListOpt )
    \item AfterAssign $\rightarrow$ EXPR
    \item FuncName $\rightarrow$ \texttt{Ifj} . ident
    \item FuncName $\rightarrow$ ident
    \item ArgListOpt $\rightarrow$ ArgList
    \item ArgListOpt $\rightarrow$ $\varepsilon$
    \item ArgList $\rightarrow$ Term ArgTail
    \item ArgTail $\rightarrow$ , Term ArgTail
    \item ArgTail $\rightarrow$ $\varepsilon$
    \item Term $\rightarrow$ \texttt{num\_lit}
    \item Term $\rightarrow$ \texttt{str\_lit}
    \item Term $\rightarrow$ \texttt{null}
    \item Term $\rightarrow$ ident
    \item Term $\rightarrow$ gident
    \item EXPR $\rightarrow$ LogicOr
    \item LogicOr $\rightarrow$ LogicAnd LogicOrTail
    \item LogicOrTail $\rightarrow$ \texttt{||} LogicAnd LogicOrTail
    \item LogicOrTail $\rightarrow$ $\varepsilon$
    \item LogicAnd $\rightarrow$ Equality LogicAndTail
    \item LogicAndTail $\rightarrow$ \texttt{\&\&} Equality LogicAndTail
    \item LogicAndTail $\rightarrow$ $\varepsilon$
    \item Equality $\rightarrow$ IsExpr EqualityTail
    \item EqualityTail $\rightarrow$ $(== \mid !=)$ IsExpr EqualityTail
    \item EqualityTail $\rightarrow$ $\varepsilon$
    \item IsExpr $\rightarrow$ Relational IsExprTail
    \item IsExprTail $\rightarrow$ \texttt{is} TypeKeyword IsExprTail
    \item IsExprTail $\rightarrow$ $\varepsilon$
    \item TypeKeyword $\rightarrow$ \texttt{KEYWORD(String)}
    \item TypeKeyword $\rightarrow$ \texttt{KEYWORD(Num)}
    \item TypeKeyword $\rightarrow$ \texttt{KEYWORD(Null)}
    \item Relational $\rightarrow$ Additive RelationalTail
    \item RelationalTail $\rightarrow$ $(< \mid <= \mid > \mid >=)$ Additive RelationalTail
    \item RelationalTail $\rightarrow$ $\varepsilon$
    \item Additive $\rightarrow$ Multiplicative AdditiveTail
    \item AdditiveTail $\rightarrow$ $(+ \mid -)$ Multiplicative AdditiveTail
    \item AdditiveTail $\rightarrow$ $\varepsilon$
    \item Multiplicative $\rightarrow$ Unary MultiplicativeTail
    \item MultiplicativeTail $\rightarrow$ $( * \mid / \mid \% )$ Unary MultiplicativeTail
    \item MultiplicativeTail $\rightarrow$ $\varepsilon$
    \item Unary $\rightarrow$ $( ! \mid + \mid - )$ Unary
    \item Unary $\rightarrow$ Primary
    \item Primary $\rightarrow$ \texttt{num\_lit}
    \item Primary $\rightarrow$ \texttt{str\_lit}
    \item Primary $\rightarrow$ \texttt{null}
    \item Primary $\rightarrow$ gident
    \item Primary $\rightarrow$ ( EXPR )
    \item Primary $\rightarrow$ ident PrimaryIdentTail
    \item Primary $\rightarrow$ \texttt{Ifj} . ident ( ArgListOpt )
    \item PrimaryIdentTail $\rightarrow$ ( ArgListOpt )
    \item PrimaryIdentTail $\rightarrow$ $\varepsilon$
\end{enumerate}
